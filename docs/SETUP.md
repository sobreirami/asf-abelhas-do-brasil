# ASF Abelhas do Brasil — Setup

## Prerequisites

- Node.js 22.13+, 24.3+ or 26+ (required by Expo SDK 58 / React Native 0.88; odd-numbered releases such as 23 and 25 are not supported) — 24.12+ recommended, since firebase 13's `@firebase/*` packages declare `node >=24.12`
- npm 10+
- Expo CLI: bundled with the `expo` package — run it with `npx expo` (the global `expo-cli` package is deprecated)
- EAS CLI: `npm install -g eas-cli`
- Xcode 26.4+ (iOS, macOS only)
- Android Studio (Android)
- JDK 17 (e.g. `brew install --cask zulu@17`) and `ANDROID_HOME=$HOME/Library/Android/sdk` exported in your shell profile (required by `npm run android`)
- Firebase project at [console.firebase.google.com](https://console.firebase.google.com)
- Expo account at [expo.dev](https://expo.dev)

---

## Installation

```bash
git clone https://github.com/sobreirami/asf-abelhas-do-brasil.git
cd asf-abelhas-do-brasil

cp .env.example .env   # fill in Firebase credentials
npm install
```

## Environment variables

Credentials are injected via `expo-constants` from `app.config.js → extra` (loaded from `.env` with `dotenv`). The `firebase.ts` service reads them at runtime — **never hardcode credentials in source code**.

```bash
# .env
FIREBASE_API_KEY=...
FIREBASE_AUTH_DOMAIN=...
FIREBASE_PROJECT_ID=...
FIREBASE_STORAGE_BUCKET=...
FIREBASE_MESSAGING_SENDER_ID=...
FIREBASE_APP_ID=...
```

> `.env` is gitignored. Never commit it.

## Data import scripts

All scripts live in `scripts/` and run with Node.js directly (no transpilation needed).

```bash
# 1. Place your Firebase Admin SDK key (gitignored)
cp <downloaded-key>.json serviceAccountKey.json

# 2. Import base species data
node scripts/import-species.js

# 3. Enrich with meliponiculture fields (rationalBox, trapNest)
node scripts/enrich-meliponiculture.js

# 4. Fetch iNaturalist photos and attach to each species
node scripts/fetch-inaturalist-photos.js

# 5. Backfill cover photos on existing documents
node scripts/backfill-covers.js
```

`scripts/species-data.json` — consolidated dataset with all species data and iNaturalist photos, used by the import scripts.

> `serviceAccountKey.json` is gitignored. Never commit it.

## Firestore indexes

Composite indexes are needed for filtered + ordered queries. If you see an index error in the console, follow the link provided by Firebase to create it.

Queries in use:

| Query                                                  | Index required         |
| ------------------------------------------------------ | ---------------------- |
| `orderBy('commonName') + limit(20)`                    | Default (auto-created) |
| `where('regions', 'array-contains', v) + orderBy(...)` | Composite              |
| `where('behavior', '==', v) + orderBy(...)`            | Composite              |
| `where('featured', '==', true) + limit(10)`            | Single field           |

## Running the app

### Expo Go (quick preview)

```bash
npm start
# Scan the QR code with the Expo Go app
```

Some native modules (reanimated, glass effects) may not work in Expo Go.

### Simulator / emulator (recommended for development)

```bash
npm run ios        # iOS simulator
npm run android    # Android emulator
```

`android/` and `ios/` are generated by `npx expo prebuild` (Continuous Native Generation) and are gitignored. `npm run ios` / `npm run android` reuse an existing native folder, so regenerate it after upgrading the Expo SDK or changing `app.config.js`:

```bash
npx expo prebuild --clean   # or --platform android / --platform ios
```

Never edit `android/` or `ios/` by hand — native settings belong in `app.config.js` and config plugins (e.g. `expo-build-properties`).

## Upgrading the Expo SDK

```bash
npx expo install expo@^<version> --fix   # bump expo and align every SDK-managed package
npx expo install --check                 # expect "Dependencies are up to date"
npx expo-doctor                          # project health checks
npx expo prebuild --clean                # regenerate android/ and ios/
```

Read the target SDK's changelog on [expo.dev/changelog](https://expo.dev/changelog) first. `expo-doctor` does not schema-validate `app.config.js` (it only checks a static `app.json`), so double-check new config keys against the [Expo config reference](https://docs.expo.dev/versions/latest/config/app/).

## OTA updates (Expo Updates)

OTA updates are **not enabled yet**: `expo-updates` is not installed and `app.config.js` has no `updates` block. To enable them (this adds a native module, so a new binary is required):

```bash
npx expo install expo-updates
eas update:configure   # adds updates.url, runtimeVersion and a channel per build profile
```

Then rebuild and ship the new binary. From that point on, JS/asset-only fixes can be published without a new App Store / Play Store submission:

```bash
eas update --branch production --message "fix: species detail crash"
```
